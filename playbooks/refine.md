# Refine Playbook

Use when the incumbent visual system and product behavior should remain recognizable while hierarchy, typography, spacing, responsive behavior, interaction, or polish improves.

## Process

1. **Context:** inspect the affected surface, owning components, shared tokens, current states, and existing visual language.
2. **Direction:** state the constraint being preserved and write only the decisions that change the current result. A full Visual Thesis is optional unless the refinement changes the surface's communication mechanism.
3. **Shape:** preserve route topology and content ownership unless the request explicitly changes them; define the smallest hierarchy or state correction.
4. **Implement:** keep behavior and accessibility infrastructure stable, then compose the correction through existing primitives.
5. **Evidence:** verify the affected state, one representative responsive width, and any interaction changed. Record what was not exercised.

## Load

Always load the relevant `references/visual-review.md` guidance. Add domain references only for the decision being changed.

## Stop

Stop when the requested constraint is satisfied, no new structural or legibility problem was introduced, and remaining differences are preference-only.
